GUÍA PASO A PASO: APP EN GITHUB + BASE DE DATOS EN EL ACER NITRO 5
=====================================================================
Cómo queda armado:
  - La app (lo que ven las personas) vive en GitHub Pages, gratis.
  - El servidor y la base de datos viven en el Acer, en tu casa.
  - Tailscale Funnel le da al Acer una dirección https segura en internet,
    sin tocar el router.
  Mientras el Acer esté encendido, con internet y con el servidor abierto,
  el sistema funciona. Si se apaga, la app muestra "El sistema no está
  disponible" (no se pierden datos).

---------------------------------------------------------------------
PARTE A · PREPARAR EL ACER (una sola vez)
---------------------------------------------------------------------
A1. Que no se duerma
    Inicio › Configuración › Sistema › Inicio/apagado y batería › Pantalla
    y suspensión › "Poner el dispositivo en suspensión": Nunca (con
    cargador). Déjalo siempre enchufado.

A2. Instalar Node.js
    Entra a https://nodejs.org, descarga la versión "LTS" para Windows e
    instálala con "Siguiente" en todo.

A3. Instalar PostgreSQL (la base de datos)
    Entra a https://www.postgresql.org/download/windows/ › "Download the
    installer" › versión 16 para Windows x86-64.
    En el instalador deja todo por defecto. Cuando pida contraseña para el
    usuario "postgres", inventa una y ANÓTALA. Puerto: 5432. Al final
    desmarca "Stack Builder".

A4. Crear la base del Hub
    Abre el menú Inicio y busca "SQL Shell (psql)". Presiona Enter en las
    preguntas (Server, Database, Port, Username) hasta que pida la
    contraseña: escribe la de "postgres" (no se ve al escribir, es normal).
    Luego escribe estas dos líneas, una por una, con Enter
    (cambia ClaveDelHub2026 por una tuya y anótala):
        CREATE USER hub WITH PASSWORD 'ClaveDelHub2026';
        CREATE DATABASE hub OWNER hub;
    Cierra la ventana.

A5. Copiar el proyecto
    Descomprime keypoint-hub-providencia.zip en C:\hub
    (debe quedar C:\hub\keypoint-hub-providencia\package.json).

---------------------------------------------------------------------
PARTE B · SUBIR LA APP A GITHUB
---------------------------------------------------------------------
B1. Crea una cuenta en https://github.com si no tienes.
B2. Instala GitHub Desktop: https://desktop.github.com e inicia sesión.
B3. En GitHub Desktop: File › Add local repository › elige
    C:\hub\keypoint-hub-providencia. Si dice que no es un repositorio,
    toca "create a repository" › Create repository.
B4. Escribe "Primera versión" abajo a la izquierda › Commit to main ›
    Publish repository. Desmarca "Keep this code private" (GitHub Pages
    gratis necesita repositorio público) › Publish.
B5. En el navegador abre tu repositorio en github.com ›
    Settings › Pages › en "Source" elige "GitHub Actions".
B6. Pestaña Actions: espera el círculo verde (2 a 3 minutos).
    Tu app queda en https://TU-USUARIO.github.io/keypoint-hub-providencia/
    Por ahora funciona en modo demo. ANOTA esa dirección.

---------------------------------------------------------------------
PARTE C · ENCENDER EL SERVIDOR EN EL ACER
---------------------------------------------------------------------
C1. En C:\hub\keypoint-hub-providencia copia el archivo .env.example,
    pégalo en la misma carpeta y renombra la copia a .env
    (si Windows oculta extensiones: Vista › Mostrar › Extensiones de
    nombre de archivo).
C2. Abre .env con el Bloc de notas y cambia estas líneas:
        DATABASE_URL=postgres://hub:ClaveDelHub2026@localhost:5432/hub
        SESSION_SECRET=   (escribe una frase larga sin espacios, unas 40 letras)
        ALLOWED_ORIGIN=https://TU-USUARIO.github.io
    Guarda.
C3. Abre la carpeta, haz clic en la barra de dirección, escribe cmd y
    Enter. En la ventana negra escribe, una por una:
        npm install
        npm run db:init -- --demo
    (--demo carga los datos de ejemplo para la primera prueba.
     Para operar con personas reales usa después:
        npm run db:init -- --clean --reset
     antes, en .env, pon ADMIN_PASSWORD con una clave de 10+ caracteres.)
C4. Cierra esa ventana y haz doble clic en iniciar-hub.bat.
    Debe decir "Keypoint Hub Providencia en http://localhost:8080".
    Prueba abriendo http://localhost:8080 en el Acer.
    Si Windows pregunta por el firewall, toca "Permitir".
    Esa ventana debe quedar ABIERTA (puedes minimizarla).

---------------------------------------------------------------------
PARTE D · DARLE AL ACER UNA DIRECCIÓN EN INTERNET (Tailscale)
---------------------------------------------------------------------
D1. Descarga Tailscale para Windows en https://tailscale.com/download,
    instálalo e inicia sesión (con Google sirve).
D2. Abre el menú Inicio, busca "cmd", clic derecho › Ejecutar como
    administrador. Escribe:
        tailscale funnel --bg 8080
    La primera vez te mostrará un enlace para activar Funnel: ábrelo,
    acepta, y vuelve a escribir el mismo comando.
D3. Te mostrará una dirección como:
        https://acer-nitro.tail1234.ts.net
    ANÓTALA. Ábrela desde tu celular con datos móviles: debe verse la app.
    Con --bg queda funcionando aunque cierres la ventana y vuelve sola al
    reiniciar mientras Tailscale esté abierto.

---------------------------------------------------------------------
PARTE E · CONECTAR LA APP DE GITHUB CON EL ACER
---------------------------------------------------------------------
E1. En github.com abre tu repositorio › archivo config.web.js ›
    lápiz (Edit).
E2. Cambia la última línea:
        window.HUB_CONFIG = null;
    por (con TU dirección de Tailscale, sin barra al final):
        window.HUB_CONFIG = { api: "https://acer-nitro.tail1234.ts.net" };
E3. Commit changes › Commit changes. Espera el círculo verde en Actions.
E4. Abre https://TU-USUARIO.github.io/keypoint-hub-providencia/
    Ya no aparecen las cuentas de demostración: ahora usa la base del Acer.
    Entra con roderick.grez@mayor.cl / demo1234 (si cargaste --demo).
    Si en tu equipo se ve la versión anterior, recarga con Ctrl + F5.

---------------------------------------------------------------------
CADA DÍA DE PRUEBA
---------------------------------------------------------------------
  1. Encender el Acer, enchufado y con internet.
  2. Doble clic en iniciar-hub.bat (dejar la ventana abierta).
  3. Verificar que Tailscale esté conectado (ícono junto al reloj).
  4. Probar la dirección de GitHub desde un celular.

RESPALDO (recomendado a diario)
  IMPORTANTE: el archivo C:\hub\keypoint-hub-providencia\.data-key es la clave que
  cifra RUT, correos y teléfonos. Cópialo una vez a un pendrive o lugar seguro.
  Sin ese archivo, un respaldo de la base no sirve.
  En cmd dentro de la carpeta de PostgreSQL (C:\Program Files\PostgreSQL\16\bin):
      pg_dump -U hub -d hub -F c -f C:\hub\respaldo.dump
  Copia ese archivo y la carpeta C:\hub\keypoint-hub-providencia\uploads
  a un pendrive o a la nube.

SI ALGO FALLA
  - "El sistema no está disponible": el Acer está apagado, sin internet,
    o la ventana de iniciar-hub.bat se cerró.
  - La ventana del servidor muestra "password authentication failed":
    la clave en DATABASE_URL no coincide con la del paso A4.
  - La app no entra y en el navegador sale un error de "CORS":
    ALLOWED_ORIGIN en .env no coincide con https://TU-USUARIO.github.io
    (sin barra final y sin /keypoint-hub-providencia). Reinicia el servidor.
  - Tailscale no da dirección: revisa que Funnel quedó activado en
    https://login.tailscale.com/admin y repite D2.
